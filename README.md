# Тыквенная полночь 🎃 — Telegram → Яндекс Музыка

Worker без платных библиотек и без нейросети. Добавляет треки по точным ссылкам в существующий плейлист `7f245f47-ab83-0ca6-96b1-e2f6f2027bd3`.

## Текущая установка и восстановление

- Telegram: [@YAMusicPack_bot](https://t.me/YAMusicPack_bot).
- Cloudflare Worker: `pumpkin-playlist-bot`.
- Панель проверки: https://pumpkin-playlist-bot.kostylink2003.workers.dev/.
- Плейлист: https://music.yandex.ru/playlists/7f245f47-ab83-0ca6-96b1-e2f6f2027bd3.
- Разрешённая группа задаётся в `ALLOWED_CHAT_IDS` файла `wrangler.jsonc`.

Код и настройки сохранены в репозитории. Значения трёх секретов хранятся только в Cloudflare и не включены в Git. При переносе в новый аккаунт их понадобится добавить заново.

После клонирования установите Node.js LTS, выполните `npm ci`, затем `npm test`. Для обновления существующего Worker: `npx wrangler login --device`, затем `npm run deploy`. В Cloudflare должны быть разрешения на чтение аккаунта и изменение Workers Scripts. Используйте тот же аккаунт и имя Worker; параметры из `wrangler.jsonc` применяются при публикации. Развёртывание не запускается автоматически при изменении репозитория.

Проверено: 9 локальных тестов; авторизация обоих сервисов и чтение плейлиста из опубликованного Worker. Финальное добавление новой песни из Telegram нужно проверять командой `/add` в разрешённой группе.

## Команды

- `/add@имя_бота https://music.yandex.ru/album/7/track/42` — добавить трек.
- `/add@имя_бота` в ответ на сообщение со ссылкой — добавить трек из ответа.
- `/playlist` — ссылка на плейлист.
- `/id@имя_бота` — ID текущего чата и отправителя.
- `/help` — помощь.

Пока `ALLOWED_CHAT_IDS` пуст, добавление запрещено всем. Если заполнить `ALLOWED_USER_IDS`, разрешены только указанные люди внутри разрешённых чатов. По умолчанию все обычные участники разрешённой группы могут добавлять треки. Удалять треки, менять название и выбирать другой плейлист через Telegram нельзя. Режим приватности Telegram можно оставить включённым: в группе используйте команды с `@имя_бота`.

## Развёртывание

1. Создайте отдельного бота в [BotFather](https://t.me/BotFather), добавьте его в группу. Админские права не нужны.
2. Создайте Cloudflare Worker `pumpkin-playlist-bot` через Hello World, откройте Edit code и замените содержимое на `worker.mjs`. Либо используйте Wrangler: `npx wrangler deploy` из этой папки.
3. Добавьте **Secrets** в Cloudflare → Worker → Settings → Variables and Secrets:
   - `TELEGRAM_BOT_TOKEN` — токен нового бота.
   - `YANDEX_TOKEN` — OAuth-токен аккаунта владельца плейлиста. Это доступ к аккаунту, а не отдельному плейлисту: хранить только как секрет.
   - `SETUP_SECRET` — случайная строка 32–256 символов (латинские буквы, цифры, `_`, `-`). Защищает панель управления и webhook.
4. Добавьте обычные **Text** переменные:
   - `PLAYLIST_UUID` = `7f245f47-ab83-0ca6-96b1-e2f6f2027bd3`
   - `BOT_USERNAME` = имя нового бота без `@`.
   - `ALLOWED_CHAT_IDS` = сначала пусто, затем ID вашей группы (обычно отрицательное число).
   - `ALLOWED_USER_IDS` = пусто или список Telegram ID через запятую.
5. Откройте HTTPS-адрес Worker. Введите только `SETUP_SECRET`, нажмите «Проверить подключения». Проверка читает аккаунт Яндекса, плейлист и профиль Telegram, ничего не добавляет.
6. Нажмите «Подключить Telegram». Будет установлен webhook с секретным заголовком и команды нового бота. Существующий WoW-бот не затрагивается.
7. Напишите `/id@имя_бота` в группе. Внесите ID группы в `ALLOWED_CHAT_IDS` и примените настройки.
8. Проверка без изменения плейлиста: отправьте ссылку на уже имеющийся трек, например `/add@имя_бота https://music.yandex.ru/album/7018993/track/50684233`. Ответ должен быть «Уже есть в плейлисте».
9. Добавьте новый трек и проверьте его наличие в Яндекс Музыке.

## Токен Яндекса

Используется неофициальный API. [Документация получения токена](https://github.com/MarshalX/yandex-music-api/blob/main/docs/source/token.md) описывает Device Flow и браузерный OAuth. Авторизацию и выдачу доступа выполняет владелец самостоятельно. Не публикуйте токен и URL с ним в Telegram, чате, GitHub или логах. Если токен истёк, обновите секрет `YANDEX_TOKEN`.

## Проверки и ограничения

`node --test` запускает локальные тесты без токенов и внешних запросов: разбор ссылок, доступы, дубли, конфликт ревизий, неоднозначный сетевой сбой, защита webhook.

Код добавляет трек в конец, проверяет владельца плейлиста и наличие добавленного ID. Повторные доставки Telegram не создают дубликатов ID трека. Две версии одной песни с разными ID считаются разными записями. При конфликте ревизии список читается заново. При временной ошибке webhook отвечает 503, чтобы Telegram повторил доставку; кратковременные повторные текстовые ответы возможны при неоднозначном сетевом сбое Telegram.

Короткие ссылки не раскрываются, произвольные URL не запрашиваются. Поддержаны прямые HTTPS-ссылки на домены Яндекс Музыки. Автоматически достоверно определить AI-происхождение записи нельзя: участники должны добавлять проверенные исполнения. Бот не утверждает, что умеет это проверять.

Доступность Яндекс API из Cloudflare и добавление с реальным токеном нужно проверить после настройки. До успешной проверки на живом сервисе развёртывание не считается завершённым.
