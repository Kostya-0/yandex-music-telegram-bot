# Telegram → Яндекс Музыка

Бот позволяет участникам Telegram-группы добавлять треки в плейлист Яндекс Музыки по ссылке. Работает на Cloudflare Workers: постоянно включённый компьютер не нужен.

Эта инструкция — для установки **своей копии**, со своим Telegram-ботом, своим плейлистом и своим аккаунтом Cloudflare. Менять JavaScript-код для выбора другого плейлиста не требуется.

## Что понадобится

- Telegram и группа, из которой будут приходить команды.
- Аккаунт Яндекса с плейлистом, которым вы владеете.
- Аккаунт [Cloudflare](https://dash.cloudflare.com/).
- [Node.js](https://nodejs.org/) версии 22 или новее и Git на компьютере установки. После настройки компьютер можно выключить.

Бот проверяет разрешённую группу, владельца плейлиста и отсутствие дублей по ID трека. Участники группы не получают доступ к аккаунту владельца. Используется неофициальный API Яндекс Музыки; после изменений сервиса интеграцию иногда приходится обновлять. Лимиты тарифа Workers смотрите в [документации Cloudflare](https://developers.cloudflare.com/workers/platform/pricing/).

## 1. Скачайте проект

Можно сначала сделать Fork репозитория в свой GitHub и клонировать свой форк. Для установки исходной версии:

```sh
git clone https://github.com/Kostya-0/yandex-music-telegram-bot.git
cd yandex-music-telegram-bot
npm ci
npm test
```

Тесты работают без токенов и не обращаются к реальным сервисам.

## 2. Создайте своего Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Выберите название и свободное имя, заканчивающееся на `bot`.
3. Сохраните выданный токен для секрета `TELEGRAM_BOT_TOKEN` в Cloudflare.
4. Запомните имя бота без `@`: это `BOT_USERNAME`.
5. Добавьте бота в свою группу. Администратором делать его не нужно.

Используйте отдельного бота для независимой установки: у одного Telegram-бота один webhook. Повторное подключение того же токена к другому Worker переключит доставку команд на него. Режим приватности Telegram можно оставить включённым; в группе обращайтесь командой с именем бота.

## 3. Подготовьте свой плейлист и токен Яндекса

1. Создайте плейлист в Яндекс Музыке или выберите существующий **свой** плейлист.
2. Откройте его в браузере. Из адреса вида `https://music.yandex.ru/playlists/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` скопируйте часть после `/playlists/`. Это `PLAYLIST_UUID`, не полный URL.
3. Получите OAuth-токен аккаунта **владельца этого плейлиста** по [инструкции библиотеки](https://github.com/MarshalX/yandex-music-api/blob/main/docs/source/token.md).

Браузерный способ из этой инструкции: откройте [авторизацию Яндекса](https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d) в браузере, где выполнен вход в нужный аккаунт. Проверьте аккаунт и запрашиваемый доступ перед подтверждением. В адресе возврата может появиться `#access_token=...&token_type=...`. Скопируйте только значение между `access_token=` и следующим `&`, без URL и префикса `OAuth`. Если страница слишком быстро перенаправляет дальше, используйте Device Flow из инструкции библиотеки.

Токен даёт доступ к аккаунту Яндекс Музыки, а не только к одному плейлисту. Не публикуйте его в Git, Telegram, скриншотах или обычных текстовых переменных Cloudflare. Ниже для него предусмотрен Secret.

## 4. Заполните конфигурацию своей установки

**Не публикуйте проект с настройками автора из исходного `wrangler.jsonc`.** Сначала замените их шаблоном.

Windows PowerShell:

```powershell
Copy-Item wrangler.example.jsonc wrangler.jsonc
```

macOS / Linux:

```sh
cp wrangler.example.jsonc wrangler.jsonc
```

Откройте `wrangler.jsonc` и заполните поля:

| Поле | Ваше значение |
| --- | --- |
| `name` | Имя вашего Worker, например `my-music-playlist-bot`. Латинские буквы, цифры и дефисы. |
| `vars.PLAYLIST_UUID` | UUID вашего плейлиста из предыдущего шага. |
| `vars.BOT_USERNAME` | Имя вашего Telegram-бота без `@`. |
| `vars.ALLOWED_CHAT_IDS` | Пока пустая строка: ID группы получите после подключения. |
| `vars.ALLOWED_USER_IDS` | Пустая строка — все участники разрешённой группы. Для ограничения — Telegram ID пользователей через запятую. |

Остальные поля оставьте как есть. **Токены в этот файл не вставляйте.** Пока список групп пуст, добавление запрещено всем; команда `/id` работает для завершения установки.

## 5. Опубликуйте Worker в своём Cloudflare

```sh
npx wrangler login --device --scopes account:read user:read workers_scripts:write
```

Wrangler покажет адрес и одноразовый код. Откройте адрес в том же обычном браузере, где выполнен вход в Cloudflare, введите код и подтвердите доступ официальному приложению Wrangler. Оно получает чтение аккаунта и управление скриптами Workers. Если аккаунтов несколько, выберите нужный.

Затем:

```sh
npm run deploy
```

Wrangler создаст Worker с именем из вашего конфига и напечатает HTTPS-адрес вида `https://YOUR_WORKER.YOUR_SUBDOMAIN.workers.dev`. Сохраните **свой адрес**: это панель настройки и адрес приёма команд. На этом этапе Telegram ещё не подключён.

При ошибке `No access to the specified resource` проверьте аккаунт и разрешение **Workers Scripts Write**, затем повторите вход. При ошибке CSRF-cookie сначала откройте основной сайт Cloudflare, войдите в аккаунт и повторите вход Wrangler в этом же браузере. Просроченный код получите заново.

## 6. Добавьте три секрета

Создайте ключ управления на своём компьютере:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Сохраните результат в менеджере паролей: это ваш `SETUP_SECRET`. Он понадобится на странице настройки. Допустимы 32–256 латинских букв, цифр, дефисов и подчёркиваний.

Выполните команды по одной. Каждая предложит ввести значение секрета:

```sh
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put YANDEX_TOKEN
npx wrangler secret put SETUP_SECRET
```

| Секрет | Что ввести |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота из BotFather, обычно вида `123456:ABC...`. |
| `YANDEX_TOKEN` | Только OAuth-токен Яндекс Музыки владельца плейлиста. |
| `SETUP_SECRET` | Случайный ключ управления, созданный выше. |

Альтернатива этим трём командам: Cloudflare → Workers & Pages → **ваш Worker** → Settings → Variables and Secrets → Add → тип **Secret**. Используйте имена из таблицы и примените изменения. Внешний вид панели может меняться; важно выбрать Secret, а не Text.

## 7. Проверьте подключения и включите Telegram

1. Откройте HTTPS-адрес **своего Worker**, выданный при публикации.
2. В поле `SETUP_SECRET` введите ключ управления. Токены Telegram и Яндекса на этой странице вводить не нужно.
3. Нажмите **«1. Проверить подключения»**.
4. Убедитесь, что оба сервиса показывают `ok: true`, имя бота и название плейлиста соответствуют вашей установке.
5. Нажмите **«2. Подключить Telegram»** и дождитесь `telegramConnected: true`.

Это устанавливает защищённый webhook и список команд. Если проверка показывает ошибку, сначала исправьте соответствующий токен, имя бота или доступ к плейлисту.

## 8. Разрешите свою группу

1. В Telegram-группе отправьте `/id@YOUR_BOT_NAME`, заменив имя на настоящее имя вашего бота.
2. Из ответа возьмите **ID чата**, не ID пользователя. Сохраните знак минус, если он есть.
3. Впишите ID строкой в `vars.ALLOWED_CHAT_IDS` своего конфига. Для нескольких групп перечислите ID через запятую.
4. При необходимости заполните `ALLOWED_USER_IDS`. Пустое значение разрешает всех обычных участников разрешённых групп.
5. Примените конфигурацию:

```sh
npm run deploy
```

Обновление того же Worker сохраняет Cloudflare Secrets. Повторно подключать Telegram после каждой публикации не нужно, пока адрес Worker и ключ управления не менялись. Снова нажмите «Проверить подключения»: ваш ID должен появиться в `allowedChats`.

## 9. Проверьте установку в Telegram

Заменяйте `YOUR_BOT_NAME` на настоящее имя своего бота:

| Команда | Результат |
| --- | --- |
| `/help@YOUR_BOT_NAME` | Помощь по командам. |
| `/playlist@YOUR_BOT_NAME` | Ссылка на настроенный вами плейлист. |
| `/add@YOUR_BOT_NAME https://music.yandex.ru/album/ALBUM_ID/track/TRACK_ID` | Добавление трека. Вставьте реальную ссылку из меню «Поделиться». |
| `/add@YOUR_BOT_NAME` в ответ на сообщение со ссылкой | Добавление трека из исходного сообщения. |

Сначала отправьте ссылку на трек, который **уже есть в вашем плейлисте**. Ожидаемый ответ — «Уже есть в плейлисте». Затем отправьте новую песню, дождитесь «Добавлено» и проверьте её наличие в Яндекс Музыке. Только после этой проверки установка подтверждена целиком.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Бот молчит в группе | Бот добавлен; команда адресована его настоящему имени; webhook подключён; группа есть в `ALLOWED_CHAT_IDS`. |
| `/id` работает, а `/add` молчит | Внесён ID чата, не пользователя; конфигурация опубликована; при заполненном `ALLOWED_USER_IDS` отправитель включён в список. |
| Ошибка Telegram при проверке | Токен от нужного бота; в секрет не попали текст BotFather, кавычки или URL; `BOT_USERNAME` совпадает. |
| Ошибка Яндекса при проверке | В секрете только токен; аккаунт владеет плейлистом; токен не истёк; API доступен из Cloudflare. |
| Неверный UUID | Указана часть после `/playlists/`, без полного URL и параметров. |
| Ссылка не принимается | Нужна прямая HTTPS-ссылка на отдельный трек Яндекс Музыки. Короткие ссылки, альбомы целиком и другие сервисы не поддерживаются. |
| После deploy настройки из панели пропали | Wrangler применяет `vars` из локального конфига. Храните обычные настройки своей установки в нём, а токены — в Cloudflare Secrets. |

## Обновление и использование для другого плейлиста

- Сохраните свой `wrangler.jsonc` перед обновлением: имя Worker, имя бота, UUID плейлиста и списки доступа.
- Скачайте обновления исходников, выполните `npm ci`, `npm test`, затем `npm run deploy` из папки своей установки. При обновлении **не копируйте шаблон поверх действующего конфига**.
- Для другого своего плейлиста в этой же установке замените `PLAYLIST_UUID`. Если владелец другой, замените и секрет `YANDEX_TOKEN`. Опубликуйте конфиг и проверьте подключения.
- Для независимой второй установки используйте другую папку проекта, отдельное имя Worker, отдельного Telegram-бота, свои секреты и свой конфиг. Повторите шаги выше.
- GitHub хранит исходники. Изменение репозитория само по себе не обновляет Cloudflare: автоматическое развёртывание в этом проекте не настроено.

## Ограничения

- Один плейлист на установку. Несколько разрешённых групп добавляют треки в этот же плейлист.
- Дубли определяются по ID трека. Разные издания одной песни могут иметь разные ID.
- При конфликте изменений бот перечитывает плейлист и повторяет попытку. Временные ошибки могут задержать ответ из-за повторной доставки Telegram.
- Бот не скачивает аудио и не использует нейросеть. При этом достоверно определить AI-происхождение записи он не может: участники сами выбирают проверенные исполнения.
